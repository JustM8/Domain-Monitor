# Підключення дочірнього сайту

Портал надсилає команди лише сайтам з увімкненим дистанційним керуванням. Моніторинг перевіряє доступність незалежно від керування і ніколи самостійно не вимикає сайт.

## Laravel: готові файли

1. Скопіювати `docs/child-site/PortalControlState.php`, `PortalControlEndpoint.php`, `EnforcePortalControl.php` у `app/PortalControl/` **дочірнього** проєкту.
2. Скопіювати `docs/child-site/portal_control.php` у його `config/portal_control.php`.
3. У `.env` дочірнього сайту вказати ID та ключ із картки сайту в порталі:

```dotenv
PORTAL_SITE_ID=123
PORTAL_SITE_TOKEN=ключ_з_картки_сайту
```

Не використовувати один ключ для кількох сайтів. Доступ до ключа в порталі мають Admin/PM. На сервері ключ зберігати поза `public`, не передавати у JavaScript, iframe, Git чи журнали.

4. У `routes/api.php` додати endpoint:

```php
Route::post('/portal/sync', \App\PortalControl\PortalControlEndpoint::class);
```

Маршрут має залишатися доступним навіть під час блокування; він перевіряє секрет у заголовку. Не додавати його до middleware входу користувача чи CSRF-перевірки вебформ. Для Laravel, де API-префікс налаштовується окремо, перевірити фактичний шлях: **POST `/api/portal/sync`**. Увесь сайт і endpoint працюють через HTTPS.

5. Додати `\App\PortalControl\EnforcePortalControl::class` до глобальних middleware дочірнього застосунку. У Laravel 10 це `$middleware` в `app/Http/Kernel.php`; у новіших структурах — реєстрація через `bootstrap/app.php`. Це власний middleware застосунку, не зміна `vendor`.
6. Надати PHP право запису в `storage/app/portal-control`. Директорія не має бути доступною через вебсервер. Зберігати її між деплоями та включити до резервного копіювання.
7. Оновити config cache дочірнього сайту. У порталі увімкнути керування та натиснути «Синхронізувати». Перевірити збіг стану й версії. Лише після цього перевірити вимкнення та повторне ввімкнення з причиною.

## Протокол для інших CMS

Портал надсилає JSON на `https://адреса-сайту/api/portal/sync`, заголовок `X-Site-Token`:

```json
{
  "site_id": 123,
  "state": "disabled",
  "version": 7,
  "issued_at": 1788998400,
  "reason": "Погоджене тимчасове вимкнення",
  "display_mode": "iframe",
  "embed_origins": ["https://client.example"]
}
```

`issued_at` — поточний Unix timestamp; наведене число ілюстративне. Приймати тільки правильний ключ, ID, допустимі поля й свіжу команду (±5 хвилин). Годинники серверів мають бути синхронізовані. Оновлення зберігати атомарно під блокуванням. Версію, меншу за збережену, відхиляти HTTP 409. Повтор тієї самої версії з тим самим вмістом підтверджувати; суперечливий повтор відхиляти.

Після надійного збереження відповісти HTTP 200:

```json
{"status":"disabled","version":7}
```

Портал визнає успіх лише при точному збігу стану та числової версії. Помилка мережі, редирект, стороння HTML-сторінка чи інший стан не є підтвердженням. Повторна синхронізація надсилає актуальну команду; її версія зростає при зміні рішення та налаштувань iframe. Зміна URL скидає керування й оновлює ключ — нову адресу потрібно підключити знову.

## Поведінка при недоступності порталу

Middleware читає локально збережений стан, не звертається до порталу на кожен запит. Останній стан зберігається при проблемах зі зв’язком: увімкнений сайт продовжує працювати, вимкнений залишається вимкненим. Після першого встановлення, до першої команди, приклад дозволяє роботу. Пошкоджений файл стану повертає 503 і потребує відновлення з резервної копії. Не видаляти цей файл під час звичайного очищення кешу.

Звичайний `php artisan down` не застосовувати для цього механізму: він може закрити endpoint повторного ввімкнення. Віддаленого видалення файлів або бази немає.

## iframe, статика та кешування

Для типу `3D` вибрати `iframe` і додати точні origins сайтів клієнтів. Middleware встановлює `Content-Security-Policy: frame-ancestors …`, зберігаючи інші CSP-директиви. Перевірити, що nginx/Apache/CDN не додають зверху `X-Frame-Options: DENY/SAMEORIGIN` або другу конфліктну CSP-політику.

**PHP middleware не перехоплює файли, які nginx/Apache або CDN віддають напряму.** Якщо 3D — статичний `index.html`, його точку входу треба провести через застосунок або реалізувати еквівалентну перевірку на вебсервері. Не кешувати керований HTML та відповіді 503 у CDN; вже завантажена в браузер 3D-сцена не зникає після вимкнення сервера. Для повного обмеження ресурсів додатково потрібні серверні правила доступу до них.

Перевірити: робота дозволеного iframe; відмова чужому origin; вимкнення публічної точки входу; доступність endpoint; повторне ввімкнення; неправильний ключ; застаріла команда; недоступність порталу.

## Межі захисту

Інтеграція має бути частиною погодженого контрактом керування. Її можна відокремити від клієнтської адмінки та зберігати у власному модулі. Власник повного доступу до коду/хостингу технічно може її прибрати; гарантувати невимикання через «вшивання у core» неможливо. Це обмежується правами хостингу та умовами договору.
